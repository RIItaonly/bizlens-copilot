# 竞品对比与成本模型

> 解决方案岗和顾问岗最容易被问的两句话："为什么不用现成平台？"、"这套东西一年要花多少钱？"
> 这一页就是答案。

## 1. 四条路线

| 维度 | 自研编排层 | 低代码平台（Dify / Coze 类） | 商业 BI + 问数 | 外包/咨询交付 |
|---|---|---|---|---|
| 2 周内出 POC | 中 | **快** | 快 | 慢 |
| 指标口径治理 | **强**（语义层可版本化） | 弱 | 中 | 取决于乙方 |
| 行级权限 / 审计 | **强** | 弱 | 中 | 取决于乙方 |
| 可回归评测 | **强** | 弱 | 弱 | 弱 |
| 首年成本 | 中 | 低 | 高（license） | **很高** |
| 供应商锁定 | 无 | **高** | 高 | 中 |
| 适合阶段 | 试点 → 推广 | POC / 内部工具 | 已有数仓的企业 | 无人力、要快速上线 |

## 2. 结论：分阶段推进

```
POC（2 周）      低代码平台快速验证"业务方愿不愿意用"
   ↓ 验证通过
试点（6 周）     自研四件套：语义层 + 权限 + 审计 + 评测
   ↓ 指标达标
推广（1 季度）   接审批流、接更多数据源
```

**判断标准**：如果客户只是要"看看效果"，低代码够了。如果要"上会、签字、追责"，四件套缺一不可。这两类需求的报价能差 5 倍，原因就在这里。

## 3. 成本模型

### 变动成本

```
单任务成本 = 输入 token × 单价 + 输出 token × 单价 + 检索/存储摊销
```

| 项 | 假设值 | 说明 |
|---|---|---|
| 单任务模型调用 | 约 8 次 | 意图解析、查询、校验、归因、报告 |
| 单次输入 / 输出 | 5k / 1k tokens | 含上下文与检索片段 |
| 单价（示例） | 输入 ¥1/M，输出 ¥2/M | 按主流国产模型量级估算 |
| **单任务成本** | **≈ ¥0.06** | 含 30% 重试余量后约 ¥0.08 |

### 固定成本（年）

| 项 | 金额（示例） | 说明 |
|---|---|---|
| 模型调用 | ¥3,000 | 按 8,000 任务/年 × ¥0.08，留余量 |
| 基础设施 | ¥3,000 | 1 台云主机 + 对象存储 + 监控 |
| 维护人力 | ¥10,000 | 0.5 人月/年（口径变更、数据源变动） |
| **合计** | **≈ ¥16,000/年** | — |

### 收益侧

```
年化收益 = 单次节省工时 × 年次数 × 人数 × 人力成本 − 年成本
```

算例（假设）：3 小时 × 40 次 × 5 人 × ¥150/小时 = ¥90,000，减去 ¥16,000，**净收益约 ¥74,000/年**。

> 注意：这个数不大。真正的价值在"口径统一"和"复核成本下降"。它们不进这张表，但在会上很值钱。这一点比报一个大数字更可信。

## 4. 敏感性

| 变量 | 变化 | 对结论的影响 |
|---|---|---|
| 任务量 ×10 | 8,000 → 80,000 | 变动成本线性上升，仍远低于人力 |
| 模型降价 50% | — | 变动成本占比本来就低，影响有限 |
| 维护人力 ×3 | 1.5 人月/年 | 净收益下降约 30%，仍为正 |
| 口径频繁变更 | 每月一次 | 维护成本可能翻倍，是主要风险 |

**结论**：这套方案的成本结构是"人力重、算力轻"，真正的风险是**口径治理没人负责**，模型贵反而是次要的。这也是为什么要设"指标负责人"。

## 5. 采购 vs 自研的判断清单

满足 3 条以上，倾向自研：

- [ ] 指标口径是核心竞争力，不能交给黑盒
- [ ] 有行级权限 / 审计 / 合规要求
- [ ] 需要按业务变化快速改流程
- [ ] 内部有 1–2 个能维护的工程师
- [ ] 计划推广到 3 个以上部门

反之，先买/先用低代码，把预算花在场景验证上。
