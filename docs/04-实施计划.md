# 八周实施计划

> 前提：业余时间推进，按**每天 3–4 小时、每周 5 天**估算（约 15–20 小时/周）。
> 原方案"四周三个系统"不现实，这里砍成一个旗舰 + 一个轻量，并把方案文档贯穿进去。

## 1. 总览

| 周 | 主题 | 关键产出 | 验收标准 |
|---|---|---|---|
| W1 | 场景与口径（不写代码） | 30 条任务清单、8 个指标口径表 | 问题清单能被非技术的人看懂 |
| W2 | 数据与语义层 | 合成数据 5 张表、`metrics.yaml`、只读查询、行级权限 | 20 条查询类任务可答且数对 |
| W3 | 单 Agent 闭环 | 意图解析 + 工具调用 + 引用 + 拒答 | 30 条任务端到端跑通 |
| W4 | 报告与审批 **（GATE）** | 结构化报告、审批流、留痕 | 见下方 gate 规则 |
| W5 | 评测 | 60 条任务集、rubric、首份评测报告 | 能给出 TSR/NAR/时延/成本 |
| W6 | 归因与建议 | 贡献度拆解、动作库、制度检索 | T4 通过率有可比基线 |
| W7 | 前端与 Demo | 界面、录屏、GIF、一键启动 | 陌生人能按 README 跑起来 |
| W8 | 收尾 | 一页纸、竞品对比、成本模型、技术报告 | 文档与报告齐备 |

## 2. 分周说明

**W1：只做两件事，不碰代码**

- 收集 30 个真实会问的问题（可找同学/导师模拟业务方）
- 和"财务角色"确认 8 个指标的口径：收入、成本、毛利率、回款率、费用率、人均产值、项目进度偏差、合同额
- 产出：`eval/tasks_v0.yaml`、`docs/metrics.md`
- ⚠️ 这周最容易跳过，也最不该跳过。口径没定，后面全是返工。

**W2：数据与语义层**

- 合成 5 张表：项目、合同、收入、成本、组织
- 用 YAML 定义指标（名称、公式、维度、口径说明、负责人）
- 查询层：只读连接、白名单、行级过滤、超时与 LIMIT
- 验收：随机抽 20 条查询任务，数字与手工计算一致

**W3：单 Agent 闭环**

- 意图 → 指标 + 维度 + 时间；调工具；组织回答；每个数字带 `evidence_id`
- 答不了时明确说"无法确定"，并说明缺什么
- 验收：30 条任务能跑完，不需要人工介入

**W4：报告与审批（GATE）**

- 报告结构：结论 → 关键数字 → 异常 → 归因 → 建议 → 附录（口径）
- 审批：通过 / 退回 / 修改意见；全程留痕
- **Gate 规则**：如果 20 条核心任务（T1/T2/T6）通过率 < 60%，**砍掉 T4 归因和 T5 制度问答**，只交付"查询 + 报告"。宁可少一个场景，不要三个都半成品。

**W5：评测**

- 补齐到 60 条，双人标注 20%
- 跑首份报告，重点看失败分类而不是总分
- 产出：`eval/report.md`

**W6：归因与建议**

- 贡献度拆解（价格/数量/成本/结构）
- 建议模板 + 动作库（动作、责任人、时限）
- 制度检索：片段 + 页码 + 引用

**W7：前端与 Demo**

- 界面三块：对话、任务执行过程、报告与审批
- 录 3 分钟视频，剪 20 秒 GIF 放 README 首屏
- `docker compose up` 一键启动

**W8：方案收尾**

- 一页纸方案（已有）、竞品对比矩阵、成本模型、技术报告
- 复盘：哪里判断错了、砍了什么、下次怎么做

## 3. 明确不做（写下来，防止自己加戏）

- ❌ 模型训练（SFT / DPO / LoRA），项目初期投入产出比极低，且容易被追问翻车
- ❌ 多 Agent 编排，默认单 Agent，除非满足方案书 D2 的三个条件
- ❌ 多租户、复杂 RBAC、移动端
- ❌ 预测模型、预算编制
- ❌ 自动写回业务系统

## 4. 时间不够时的降级顺序

1. 先砍 W6 的"建议模板"，只保留归因
2. 再砍 T5 制度问答
3. 再砍前端，用命令行 + 录屏替代
4. **最后才砍评测**，评测是这个作品最值钱的部分，砍了就和普通 Demo 没区别

## 5. 主要风险

| 风险 | 应对 |
|---|---|
| 其他事务冲突导致断更 | 每周只定 1 个"必须完成"的产出，其余可延后 |
| 合成数据不真实 | 用公开行业报告校准量级，报告里声明假设 |
| 评测标注主观 | 先定 rubric 再标注；20% 双人标注 |
| 范围蔓延 | 每周回看"明确不做"清单 |
| 做完但讲不清 | W8 强制写 90 秒自述并录音回听 |
